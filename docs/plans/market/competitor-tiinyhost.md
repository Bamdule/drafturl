1인 창업(Elston Baretto)으로 시작하여 $20K+ MRR을 달성한 인디 SaaS 성공 사례.

- **런칭**: Product Hunt 런칭 완료
- **창업자**: Elston Baretto (풀타임 전환)

## 6. DraftURL이 배워야 할 점

### 6-1. "무료의 불편함"이 수익이다

```
Tiiny Host 무료: 1사이트, 3MB → "써볼 수는 있지만 진짜 쓰려면 돈 내야 해"
DraftURL 무료:   로그인하면 30개, 5MB → "이 정도면 충분한데?" → 전환 동기 부족
```

무료 플랜이 너무 관대하면 유료 전환이 안 됨. 무료 사용자가 "이건 돈 내야겠다"고 느끼는 지점이 있어야 함.

### 6-2. SEO 콘텐츠가 성장의 전부다

Tiiny Host는 **광고 없이 SEO만으로** DA 40+, $20K MRR 달성.

DraftURL은 메타태그를 설정했지만 **검색에 걸릴 콘텐츠가 없음**. 블로그/가이드 페이지가 필수:
- "How to share HTML document via URL"
- "Best ways to share ChatGPT output as a webpage"
- "DraftURL vs PageDrop vs Tiiny Host"
- "AI가 만든 HTML을 공유하는 가장 쉬운 방법"

### 6-3. "호스팅" 포지셔닝이 돈이 된다

```
Tiiny Host: "호스팅" → 월 과금이 자연스러움 (서버 비용 인식)
PageDrop:   "공유" → 무료가 당연하게 느껴짐
DraftURL:   "공유" → 무료가 당연하게 느껴짐 ← 수익화 시 리포지셔닝 필요
```

유료화 시점에 "문서 호스팅 플랫폼" 또는 "라이브 문서 플랫폼"으로 인식 전환 고려.

### 6-4. 커스텀 도메인 = 킬러 유료 기능

Tiiny Host에서 유료 전환의 가장 큰 동기. 자기 도메인으로 문서를 서빙하면 전문적으로 보이고, 한번 설정하면 다른 서비스로 이전하기 어려움 (전환 비용).

### 6-5. 실행 순서: 기능보다 수익화가 먼저

| 순서 | Tiiny Host (성공) | DraftURL (현재) |
|------|-------------------|-----------------|
| 1 | 핵심 기능 | 핵심 기능 ✅ |
| 2 | 유료 플랜 설계 | 아직 없음 ❌ |
| 3 | SEO 콘텐츠 | 메타태그만 ⚠️ |
| 4 | Product Hunt | 아직 ❌ |
| 5 | 기능 확장 | MCP, AI 수정 계획 중 |

Tiiny Host는 기능이 적을 때부터 유료 플랜과 SEO 콘텐츠를 먼저 만들었음. 아무리 좋은 기능을 만들어도 사용자가 없으면 의미가 없고, 사용자가 있어도 돈을 안 내면 지속할 수 없음.

### 6-6. 1인 운영 + 낮은 인프라 비용 = 빠른 손익분기

Tiiny Host도 정적 호스팅이라 마진이 높음. DraftURL도 동일 구조(R2 + 개발서버).
$5K MRR만 달성해도 1인 풀타임 가능.
