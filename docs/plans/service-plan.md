# LLM 문서 공유 서비스 — 전체 계획서

> 작성일: 2026-03-21
> 벤치마킹 대상: tiiny.host

## 1. 서비스 비전 & 포지셔닝

### 한 줄 정의

> **"LLM이 만든 문서를 URL로 공유하고, AI로 계속 수정하는 플랫폼"**

### tiiny.host와의 차별점

| 구분 | tiiny.host | 본 서비스 |
|------|-----------|-----------|
| **핵심 가치** | "파일을 URL로 변환" (범용 정적 호스팅) | "LLM이 만든 문서를 즉시 공유하고 계속 수정" |
| **입력 방식** | 드래그 앤 드롭 (파일 업로드) | LLM 출력 붙여넣기 + 파일 업로드 + API 연동 |
| **수정 방식** | 파일 재업로드 (수동) | LLM 프롬프트로 실시간 수정 (AI-native) |
| **타겟 사용자** | 비개발자 범용 | LLM 사용자 (개발자, 기획자, 팀) |
| **콘텐츠 성격** | 정적 사이트 일반 | LLM 생성 문서 특화 (HTML, MD, 발표자료) |

### 핵심 가치 제안

tiiny.host가 "정적 파일 호스팅의 극단적 단순함"에 집중했다면, 본 서비스는 **"AI 생성 콘텐츠의 라이프사이클 관리"**에 집중한다. 한 번 올리고 끝나는 것이 아니라, AI를 통해 지속적으로 수정/발전시킬 수 있는 **살아있는 문서 플랫폼**이다.

## 3. 기술 스택 제안

### 프론트엔드

| 구성요소 | 선택 | 이유 |
|---------|------|------|
| 프레임워크 | **Next.js 15 (App Router)** | SSR/SSG 혼합, SEO, 파일 기반 라우팅 |
| 언어 | **TypeScript** | 타입 안전성, 팀 확장성 |
| 스타일링 | **Tailwind CSS + shadcn/ui** | 빠른 UI 개발, 일관된 디자인 시스템 |
| 에디터 | **Monaco Editor** (코드) + **Tiptap** (리치 텍스트) | HTML 직접 편집 + MD WYSIWYG |
| 상태 관리 | **Zustand** | 경량, 단순 |
| MD 렌더링 | **unified (remark + rehype)** | MD→HTML 변환 파이프라인 |

### 백엔드

| 구성요소 | 선택 | 이유 |
|---------|------|------|
| 런타임 | **Next.js API Routes + Server Actions** | 프론트와 단일 코드베이스 |
| 인증 | **NextAuth.js (Auth.js v5)** | 소셜 로그인, 세션 관리 |
| 데이터베이스 | **PostgreSQL (Supabase)** | 사용자 정보, 문서 메타데이터, 버전 히스토리 |
| 파일 저장소 | **Cloudflare R2** 또는 **Supabase Storage** | 정적 파일(HTML/CSS/이미지) 저장, S3 호환 |
| AI 연동 | **Anthropic Claude API** | 문서 수정 기능의 핵심 LLM |
| ORM | **Drizzle ORM** | 타입 안전, 경량, Next.js 친화적 |

### 인프라

| 구성요소 | 선택 | 이유 |
|---------|------|------|
| 호스팅 | **Vercel** | Next.js 최적 배포, Edge Functions |
| CDN | **Vercel Edge Network** 또는 **Cloudflare** | 배포된 문서의 글로벌 캐싱 |
| 도메인 관리 | **Cloudflare DNS** | 커스텀 도메인 기능 대비 |
| 모니터링 | **Sentry** (에러) + **Vercel Analytics** (성능) | 운영 가시성 |
| CI/CD | **GitHub Actions** | 자동 테스트, 자동 배포 |

### 아키텍처 개요

```
사용자 브라우저
    │
    ├─ 문서 작성/수정 ──→ Next.js App (Vercel)
    │                        ├─ Auth.js (인증)
    │                        ├─ Claude API (AI 수정)
    │                        ├─ PostgreSQL (메타데이터/버전)
    │                        └─ R2/Storage (정적 파일)
    │
    └─ 공유 URL 접근 ──→ CDN (캐싱) → 정적 파일 서빙
```

## 4. 사용자 플로우

### 플로우 A: 빠른 공유 (비로그인)

```
1. 랜딩페이지 접속
2. 텍스트 에디터에 HTML/MD 붙여넣기 또는 파일 드래그 앤 드롭
3. [실시간 미리보기] 확인
4. "공유하기" 클릭
5. URL 즉시 생성 (예: share.서비스.com/abc123)
6. URL 복사하여 공유
   └─ 비로그인 → 24시간 후 만료 (가입 유도)
```

### 플로우 B: AI 수정 플로우 (로그인)

```
1. 기존 문서 선택 또는 새 문서 생성
2. 우측 AI 채팅 패널에서 수정 요청 입력
   예: "표를 더 보기 좋게 정리해줘" / "영어로 번역해줘"
3. Claude API가 수정안 생성
4. diff 미리보기 → "적용" 클릭
5. 새 버전 자동 저장 (이전 버전 보존)
6. 같은 URL에 업데이트 반영
```

### 플로우 C: 팀 문서 관리 (Phase 2)

```
1. 팀 워크스페이스 생성
2. 팀원 초대 (이메일/링크)
3. 문서 생성 → 팀 내 공유
4. 팀원이 AI 수정 요청 → 버전 히스토리에 기록
5. 외부 공유: 비밀번호 보호 + 커스텀 도메인 설정
```

### 플로우 D: CLI/API 연동 (Phase 2)

```
1. API 키 발급 (대시보드에서)
2. Claude Code 또는 터미널에서:
   $ docshare deploy ./output.html --title "주간 보고서"
3. URL 반환: https://share.서비스.com/weekly-report
4. 이후 수정:
   $ docshare update weekly-report --prompt "차트 추가해줘"
```

## 5. 구현 단계

### Phase 1: MVP (4~6주)

**목표**: 핵심 가치 검증 — "붙여넣기 → URL 생성 → AI 수정"

| 주차 | 작업 | 산출물 |
|------|------|--------|
| 1주 | 프로젝트 초기 설정 (Next.js, DB, 인증) | 기본 앱 스캐폴딩, 로그인 동작 |

| 3주 | 배포 엔진 (URL 생성, 파일 저장, 정적 서빙) | 공유 URL 동작 |
| 4주 | AI 수정 기능 (Claude API 연동, diff 미리보기) | AI 채팅 패널 |

| 작업 | 설명 |

### Phase 3: 확장 (13주~)

## 6. 수익 모델

### 가격 정책

tiiny.host는 Free($0) → Tiny($9) → Solo($18) → Pro($38) 구조. 본 서비스는 **AI 수정 기능이 핵심 차별점**이므로, AI 사용량을 기준으로 차등화한다.

| 플랜 | 월 가격 | 문서 수 | AI 수정 | 기타 |
|------|---------|---------|---------|------|
| **Free** | $0 | 3개 | 월 10회 | 임시 URL (7일 만료), 5MB 제한 |
| **Starter** | $7/월 | 20개 | 월 100회 | 영구 URL, 50MB, 비밀번호 보호 |
| **Pro** | $15/월 | 무제한 | 월 500회 | 커스텀 도메인, 분석, 100MB |
| **Team** | $12/인/월 | 무제한 | 월 1000회/인 | 팀 워크스페이스, 역할 관리, API |

**가격 설정 근거**:
- tiiny.host 대비 약간 낮은 가격대로 시작 (가격 부담이 tiiny.host의 약점)
- AI 수정 횟수를 과금 축으로 삼아 비용 구조와 가치가 일치하도록 설계
- Free 플랜에서 문서 3개 + AI 10회로 충분히 가치를 체험하게 함

### 추가 수익원 (Phase 3+)

- **API 호출 종량제**: CLI/API 대량 사용 기업 대상
- **프리미엄 템플릿**: 전문 디자인 템플릿 유료 판매
- **화이트라벨**: 기업 브랜딩으로 서비스 재판매

## 7. 리스크 및 고려사항

### 기술적 리스크

| 리스크 | 심각도 | 완화 전략 |
|--------|--------|----------|
| **AI API 비용 급증** | 높음 | 플랜별 사용량 제한 + 캐싱 + 경량 모델(Haiku)을 간단한 수정에 사용 |
| **정적 파일 저장 비용** | 중간 | 비활성 문서 자동 아카이브, Free 플랜 만료 정책 |
| **악성 콘텐츠 호스팅** | 높음 | 콘텐츠 스캐닝, 신고 시스템, 이용약관 명시 |
| **XSS 등 보안 이슈** | 높음 | 사용자 HTML을 샌드박스 iframe으로 격리, CSP 헤더 적용 |

### 비즈니스 리스크

| 리스크 | 완화 전략 |
|--------|----------|
| **기존 서비스와 경쟁** | AI 수정 기능으로 명확한 차별화 + LLM 사용자 커뮤니티 집중 공략 |
| **사용자 확보 어려움** | Claude Code 생태계, AI 커뮤니티(Discord, Reddit) 타겟 마케팅 |
| **LLM 트렌드 변화** | 특정 LLM에 종속되지 않도록 멀티 모델 지원 (OpenAI, Gemini 등) |

### 법적/운영 고려사항

- **GDPR/개인정보**: 사용자 데이터 처리 방침 명확화
- **저작권**: 사용자가 업로드한 콘텐츠의 소유권/책임 명시
- **SLA**: 유료 플랜에 대한 가용성 보장 정책

## 8. 경쟁 우위 전략

### 핵심 해자(Moat): AI-Native 문서 워크플로우

```
tiiny.host:     파일 업로드 → URL (끝)
Vercel/Netlify: Git push → 빌드 → URL (개발자 전용)
본 서비스:      입력 → URL → AI로 계속 수정 → 버전 관리 (순환)
```

경쟁사는 "배포"에서 끝나지만, 본 서비스는 **배포 이후의 수정 루프**를 핵심 가치로 가져간다.

### 전략 1: LLM 생태계 깊은 통합

- **Claude Code MCP 서버** 제공 → Claude Code에서 `docshare deploy` 명령으로 즉시 배포
- **ChatGPT Custom Actions** / **Cursor 플러그인** 등 확장
- LLM 도구 사용자들의 자연스러운 워크플로우 안에 진입

### 전략 2: "붙여넣기 배포"로 최소 마찰

- tiiny.host의 강점(극단적 단순함)을 계승
- 차이점: 파일 업로드뿐 아니라 **텍스트 붙여넣기**도 지원 → LLM 출력을 복사해서 바로 배포
- 가입 없이 임시 URL 즉시 생성 (가입 유도는 만료 전 알림으로)

### 전략 3: 커뮤니티 주도 성장

- AI/LLM 관련 커뮤니티(Twitter/X, Discord, Reddit)에서 유스케이스 공유
- "Claude로 만든 발표자료를 3초 만에 공유" 같은 바이럴 콘텐츠
- 오픈소스 CLI 도구 제공 → 개발자 커뮤니티 유입

### 전략 4: 전환 비용 구축

- 버전 히스토리가 쌓일수록 이탈 비용 증가
- 팀 워크스페이스로 조직 단위 고착화
- 커스텀 도메인 연결 후 이전 부담
