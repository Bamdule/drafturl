# DraftURL — 서비스 기능 정의

> 상태: active
> 작성일: 2026-03-21
> 최종 수정일: 2026-03-22

---

## 요약

- LLM이 생성한 문서를 URL로 즉시 공유하고, AI로 지속 수정하는 플랫폼(DraftURL)의 서비스 기능 정의서
- MVP는 "붙여넣기 -> URL 생성 -> 공유" 루프 검증에 집중하며, AI 수정 기능은 Phase 2로 이관
- 비로그인(24h 만료), Free(7일), Starter 이상(영구) 등 사용자 유형별 만료 정책과 가격 체계를 정의
- Phase 1(MVP 4주) -> Phase 2(AI 수정 + 성장) -> Phase 3(팀 협업, CLI/API, 플랫폼화)의 3단계 로드맵 포함

## 1. 서비스 비전 & 포지셔닝

### 한 줄 정의

> **"LLM이 만든 문서를 URL로 공유하고, AI로 계속 수정하는 플랫폼"**

### 핵심 가치 제안

tiiny.host가 "정적 파일 호스팅의 극단적 단순함"에 집중했다면, 본 서비스는 **"AI 생성 콘텐츠의 라이프사이클 관리"**에 집중한다. 한 번 올리고 끝나는 것이 아니라, AI를 통해 지속적으로 수정/발전시킬 수 있는 **살아있는 문서 플랫폼**이다.

> tiiny.host와의 상세 비교는 [시장 분석](../market/market.md) 참조.

## 2. 핵심 기능 목록

### MVP (Phase 1) — 확정 범위

MVP의 핵심 목표는 **"붙여넣기 -> URL 생성 -> 공유"** 루프를 최소한의 마찰로 검증하는 것이다.

| 구분 | 기능 | 설명 |
|------|------|------|
| MVP | **붙여넣기 배포** | HTML/MD 텍스트를 붙여넣으면 즉시 URL 생성 |
| MVP | **단일 파일 업로드 배포** | .html/.md 파일 드래그 앤 드롭 (클라이언트에서 텍스트로 읽어 동일 API 사용) |
| MVP | **즉시 미리보기** | 배포 전 렌더링 결과 실시간 확인 (iframe + unified) |
| MVP | **고유 URL 생성** | nanoid 8자리 slug 기반 `{서비스도메인}/{slug}` 형태 URL 즉시 발급 |
| MVP | **비로그인 임시 배포** | 24시간 만료 임시 URL (가입 유도) |
| MVP | **소셜 로그인** | Google, GitHub OAuth2 로그인 |
| MVP | **내 문서 목록** | 대시보드에서 문서 관리 (수정/삭제) |
| MVP | **문서 수정/재배포** | 에디터에서 내용 변경 후 같은 URL에 반영 |
| MVP | **Markdown 기본 렌더링** | MD -> 스타일링된 HTML 자동 변환 (기본 테마) |

> **참고**: Markdown 렌더링은 LLM이 MD 출력을 빈번히 생성하므로 MVP 필수 기능으로 포함한다.

### Phase 2로 이관된 기능

아래 기능들은 MVP에서 명시적으로 제외하며, Phase 2 이후에 순차적으로 도입한다.

| 기능 | 이관 사유 |
|------|----------|
| **AI 수정 기능** (Claude API 연동) | 핵심 차별점이나, MVP에서는 배포 루프 검증에 집중. Phase 2 최우선 |
| **버전 히스토리** | AI 수정 기능과 함께 도입해야 시너지 발생 |
| **ZIP/멀티파일 업로드** | 단일 파일 배포로 MVP 검증 충분 |
| **비밀번호 보호** | 공유 편의 기능, Phase 2 |
| **커스텀 도메인** | 인프라 복잡도 높음 |
| **커스텀 slug** | MVP에서는 자동 생성 slug만 지원 |
| **팀 워크스페이스** | Phase 3 |
| **CLI / API** | Phase 3 |

## 3. 사용자 플로우

### 플로우 A: 빠른 공유 (비로그인)

```
1. 랜딩페이지 접속
2. 텍스트 에디터에 HTML/MD 붙여넣기 또는 파일 드래그 앤 드롭
3. [실시간 미리보기] 확인 (iframe 기반)
4. "공유하기" 클릭
5. URL 즉시 생성 (예: {서비스도메인}/xK9mP2nQ)
   └─ 결과 모달: "24시간 후 만료됩니다. 로그인하면 영구 보관!" + 로그인 버튼
6. URL 복사하여 공유
   └─ 비로그인 -> 24시간 후 만료 (가입 유도 안내)
7. 공유 URL 페이지 상단 바:
   └─ "이 문서는 N시간 후 만료됩니다. 나도 만들어보기 →" CTA 표시
```

> **비로그인 문서 소유권**: 비로그인 상태에서 생성된 문서는 로그인 후 소유권 이전을 지원하지 않는다. 로그인 후 새로 생성하도록 유도하여 가입 전환을 극대화한다.

### 플로우 B: 로그인 사용자 문서 관리

```
1. Google/GitHub 소셜 로그인
2. 대시보드에서 새 문서 생성 또는 기존 문서 선택
3. 텍스트 에디터에서 HTML/MD 편집
4. 실시간 미리보기 확인
5. "배포" 클릭 -> 영구 URL 발급 (Free 플랜: 7일 만료)
6. 대시보드에서 전체 문서 목록 관리 (수정/삭제)
```

### 플로우 C: AI 수정 플로우 (Phase 2)

```
1. 기존 문서 선택 또는 새 문서 생성
2. 우측 AI 채팅 패널에서 수정 요청 입력
   예: "표를 더 보기 좋게 정리해줘" / "영어로 번역해줘"
3. Claude API가 수정안 생성
4. diff 미리보기 -> "적용" 클릭
5. 새 버전 자동 저장 (이전 버전 보존)
6. 같은 URL에 업데이트 반영
```

### 플로우 D: 팀 문서 관리 (Phase 3)

```
1. 팀 워크스페이스 생성
2. 팀원 초대 (이메일/링크)
3. 문서 생성 -> 팀 내 공유
4. 팀원이 AI 수정 요청 -> 버전 히스토리에 기록
5. 외부 공유: 비밀번호 보호 + 커스텀 도메인 설정
```

### 플로우 E: CLI/API 연동 (Phase 3)

```
1. API 키 발급 (대시보드에서)
2. CLI 또는 터미널에서:
   $ drafturl deploy ./output.html --title "주간 보고서"
3. URL 반환: https://{서비스도메인}/xK9mP2nQ  (자동 생성 slug)
4. 이후 수정:
   $ drafturl update xK9mP2nQ --prompt "차트 추가해줘"
```

> **참고**: CLI 이름(`drafturl`)은 서비스명/도메인이 확정되면 변경될 수 있다. 서비스명과 도메인 결정은 별도 논의 사항이며, CLI 이름, npm 패키지명, 도메인 가용성을 함께 검토해야 한다.
> **참고**: 커스텀 slug는 Phase 2에서 도입 완료된 상태이므로, CLI에서도 `--slug my-report` 옵션으로 커스텀 slug를 지정할 수 있다.

## 4. 구현 단계

### Phase 1: MVP (4주)

**목표**: 핵심 가치 검증 — "붙여넣기 -> URL 생성 -> 공유"

| 주차 | 작업 | 산출물 |
|------|------|--------|
| 1주 | 프로젝트 초기 설정 (Spring Boot + Next.js 스캐폴딩, DB 스키마, Flyway 마이그레이션, 로컬 개발 환경(Docker Compose)) | 로컬 개발 환경 동작 |
| 2주 | CI/CD 파이프라인 + 문서 입력/배포 (붙여넣기 + 파일 업로드 + 미리보기 + URL 생성 + 정적 서빙) | 기본 앱 빌드/배포 파이프라인, 비로그인 임시 배포 동작 |
| 3주 | 소셜 로그인 (Spring Security OAuth2 + JWT) + 대시보드 (내 문서 목록/수정/삭제) | 로그인 사용자 문서 관리 |
| 4주 | MD 렌더링 + HTML 새니타이징 + 만료 스케줄러 + 버그 수정 + 성능 튜닝 | **MVP 완성** |

**Phase 1 성공 기준 (KPI)**:
- 비로그인 사용자의 "붙여넣기 -> URL 생성" 완료율 > 70%
- 문서 생성 응답 시간 < 1.5s, 문서 서빙 응답 시간 < 800ms
- 가입 전환율 (비로그인 -> 로그인) > 5%
- 일일 문서 생성 수 추이 (성장 곡선 확인)

**졸업 기준 (Phase 1 → Phase 2 전환 조건)**:
- 일일 문서 생성 수 > 50건 AND 가입 전환율 > 5%

### Phase 2: AI 수정 + 성장 기능 (5~10주)

**목표**: AI-native 차별점 구축 — "AI로 계속 수정하는 문서"

| 주차 | 작업 | 설명 |
|------|------|------|
| 5~6주 | **AI 수정 기능** | Claude API 연동, AI 채팅 패널, diff 미리보기/적용 |
| 7주 | **버전 히스토리** | 수정 이력 저장, 이전 버전 복원, 버전 간 비교 |
| 8주 | **비밀번호 보호** | 공유 링크 접근 제한 |
| 9주 | **MD 고급 렌더링** | 테마 선택, 코드 하이라이팅, 수식(KaTeX) |
| 10주 | **분석 대시보드** + **QR 코드** | 방문자 통계, 공유 편의 기능 |

**데이터 마이그레이션 전략**: 기존 데이터와의 하위 호환성을 유지하며 점진적으로 전환한다.

**Phase 2 성공 기준 (KPI)**:
- AI 수정 기능 사용률: 로그인 사용자의 > 30%가 1회 이상 사용
- AI 수정 후 재방문율: 7일 내 재접속 > 40%
- 유료 전환율 (Free -> Starter/Pro): > 3%
- 월간 활성 문서 수 1,000개 돌파

**졸업 기준 (Phase 2 → Phase 3 전환 조건)**:
- 유료 전환율 > 3% AND 월간 활성 문서 1,000개 돌파

### Phase 3: 확장 (11주~)

**목표**: 플랫폼화 — 팀 협업, 개발자 생태계

| 우선순위 | 작업 | 설명 |
|----------|------|------|
| P1 | **CLI/API 공개** | 개발자 자동화 지원 |
| P1 | **Claude Code MCP 서버** | Claude Code에서 직접 배포 |
| P1 | **팀 워크스페이스** | 다중 사용자 협업, 역할 기반 접근 제어 |
| P2 | **커스텀 도메인** | 사용자 소유 도메인 연결 + 자동 SSL |
| P2 | **템플릿 갤러리** | 발표자료, 보고서, 포트폴리오 등 AI용 템플릿 |
| P2 | **임베드 위젯** | Notion, Slack 등에 삽입 가능한 임베드 코드 |
| P3 | **발표 모드** | MD/HTML -> 슬라이드 자동 변환 |
| P2 | **국제화(i18n) 초기 준비** | UI 텍스트 외부화, 다국어 리소스 구조 설계. MVP 기본 UI 언어는 한국어이며, Phase 3에서 영어를 추가한다 |

**데이터 마이그레이션 전략**: 기존 데이터와의 하위 호환성을 유지하며 점진적으로 전환한다.

**Phase 3 성공 기준 (KPI)**:
- 팀 플랜 전환율: > 5%의 Pro 사용자가 Team 플랜으로 업그레이드
- CLI/API 일일 배포 수: 50건/일 이상
- 월간 활성 사용자(MAU) 5,000명 돌파

## 5. 만료 정책

문서의 만료 기간은 사용자 유형과 플랜에 따라 다르다.

| 사용자 유형 | 만료 기간 | 비고 |
|------------|----------|------|
| **비로그인** | **24시간** | 생성 시 `expiresAt = createdAt + 24h` 자동 설정. 스케줄러가 주기적으로 만료 문서 + R2 파일 정리 |
| **Free 플랜** | **7일** | 임시 URL. 가입 후 업그레이드 유도 |
| **Starter 이상** | **영구** (만료 없음) | `expiresAt = null`. 유료 플랜 핵심 가치 |

> 도메인 규칙 DR-1(비로그인 24h), DR-2(로그인 영구)를 기반으로 하되, 수익 모델에서 Free 플랜 차별화를 위해 7일 만료를 적용한다. Free 플랜 만료 정책은 Phase 2에서 구현한다 (MVP에서는 DR-2 그대로 로그인 사용자 영구). 상세 도메인 규칙은 [도메인 모델](../../design/domain.md) 참조.

## 6. 수익 모델

### 가격 정책

tiiny.host는 Free($0) -> Tiny($9) -> Solo($18) -> Pro($38) 구조. 본 서비스는 **AI 수정 기능이 핵심 차별점**이므로, AI 사용량을 기준으로 차등화한다.

| 플랜 | 월 가격 | 문서 수 | AI 수정 (Phase 2부터) | 만료 | 기타 |
|------|---------|---------|---------|------|------|
| **Free** | $0 | 3개 | 월 10회 | 7일 만료 | 5MB (총 저장 용량) |
| **Starter** | $7/월 | 20개 | 월 100회 | 영구 | 50MB (총 저장 용량), 비밀번호 보호 |
| **Pro** | $15/월 | 무제한 | 월 500회 | 영구 | 커스텀 도메인, 분석, 100MB (총 저장 용량) |
| **Team** | $12/인/월 (런칭 프로모션 가격) | 무제한 | 월 500회/인 | 영구 | 팀 워크스페이스, 역할 관리, API |

> **용량 참고**: 문서당 최대 크기는 5MB이며, 위 용량은 사용자(또는 팀)의 총 저장 용량을 의미한다.

**가격 설정 근거**:
- tiiny.host 대비 약간 낮은 가격대로 시작 (가격 부담이 tiiny.host의 약점)
- AI 수정 횟수를 과금 축으로 삼아 비용 구조와 가치가 일치하도록 설계
- Free 플랜에서 문서 3개 + AI 10회로 충분히 가치를 체험하게 함

**Team 플랜 가격 근거** ($12/인/월, 런칭 프로모션):
- Starter($7) 대비 인당 $5 프리미엄: 팀 워크스페이스, 역할 관리, API 접근 기능 포함
- AI 수정 월 500회/인은 Pro와 동일 수준으로, 팀 가치(협업 기능)로 차별화
- 5인 팀 기준 월 $60: tiiny.host Pro($38/계정) 대비 경쟁력 있는 수준
- 팀 규모가 커질수록 인당 비용 절감 효과가 있어 조직 단위 도입을 유도
- 런칭 프로모션 종료 후 정가($15/인/월 이상) 전환 예정, 사용량 데이터 기반으로 결정

### AI 수정 비용 추정

AI 수정 기능의 비용 구조를 사전에 파악하여 마진을 확보한다.

**1회 AI 수정당 예상 토큰 사용량**:

| 항목 | 예상 토큰 수 | 비고 |
|------|-------------|------|
| 시스템 프롬프트 | ~500 토큰 | 수정 규칙, 출력 포맷 지시 |
| 원본 문서 (입력) | ~2,000 토큰 | 평균 HTML/MD 문서 크기 |
| 사용자 수정 요청 | ~100 토큰 | "표를 정리해줘" 수준 |
| 수정된 문서 (출력) | ~2,000 토큰 | 원본과 유사한 크기 |
| **합계** | **~4,600 토큰** (입력 ~2,600 + 출력 ~2,000) | |

**모델별 1회 수정 비용 추정**:

| 모델 | 입력 단가 | 출력 단가 | 1회 수정 비용 |
