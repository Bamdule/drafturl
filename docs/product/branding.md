## 개요

이 문서는 DraftURL의 브랜드 정체성, 메시징 프레임워크, 비주얼 가이드라인, 향후 브랜드 방향성을 정의한다. DraftURL은 쿨하고 군더더기 없는 유틸리티로, 콘텐츠를 즉시 온라인에 올리는 도구다. 번거로운 절차나 설정 없이, 오직 콘텐츠 본질에 집중한다.

## 1. 핵심 가치 제안

### 5대 가치 축

| # | 가치 | 설명 |
|---|------|------|
| 1 | **즉시 퍼블리싱** | 콘텐츠를 붙여넣으면 URL이 생성된다. 전체 과정이 5초 이내. 회원가입, 빌드 프로세스, 설정 없음. |
| 2 | **제로 프릭션** | 임시 공유에는 계정이 필요 없다. CLI도, Git도, 배포 파이프라인도 없다. 콘텐츠와 수신자 사이의 장벽을 최소화한다. |
| 3 | **LLM 네이티브 워크플로** | 오늘날 사람들이 AI와 작업하는 방식에 맞춰 설계되었다. ChatGPT/Claude/Gemini의 출력을 복사하고, 붙여넣고, 공유한다. |
| 4 | **살아있는 문서** | 정적 호스팅과 달리, DraftURL의 문서는 AI 도움을 받아 지속적으로 다듬을 수 있다(Phase 2). 문서는 스냅샷이 아니라 진화하는 것이다. |
| 5 | **깔끔하고 공유 가능한 URL** | 짧고 기억하기 쉬운 URL(`drafturl.com/xK9mP2nQ`)로, Slack, 이메일, 소셜 미디어 어디에서든 전문적으로 보인다. |

### 경쟁 차별화

| 경쟁사 | 하는 일 | DraftURL의 차별점 |
|--------|---------|------------------|
| **tiiny.host** | 드래그 앤 드롭 정적 파일 호스팅 | DraftURL은 붙여넣기로 바로 퍼블리싱(파일 불필요)하며, AI 편집 기능을 추가한다. tiiny.host는 파일 호스트이고, DraftURL은 문서 플랫폼이다. |
| **Pastebin** | 일반 텍스트 공유 | Pastebin은 아무것도 렌더링하지 않는다 — 날것의 텍스트일 뿐이다. DraftURL은 HTML과 Markdown을 아름답게 렌더링하여 코드 덤프가 아닌 실제 웹 페이지를 만든다. |
| **GitHub Gist** | Git 기반 코드 스니펫 공유 | Gist는 GitHub 계정이 필요하고 GitHub UI 안에서 Markdown을 렌더링한다. DraftURL은 깔끔한 URL을 가진 독립 페이지를 생성하며, 플랫폼 UI 장식이 없다. |
| **CodePen / JSFiddle** | 프론트엔드 코드 플레이그라운드 | 이들은 실험용 개발자 도구다. DraftURL은 완성된(또는 초안) 문서를 누구에게든 공유하기 위한 도구다. |
| **Claude Artifacts** | 채팅 내 미리보기 | 공유 가능한 URL을 생성할 수 없다. 콘텐츠가 대화 안에 갇혀 있다. DraftURL은 AI 출력을 이동 가능하게 만든다. |

**한 줄 차별화:**
> tiiny.host hosts files. DraftURL hosts ideas.
> tiiny.host는 파일을 호스팅한다. DraftURL은 아이디어를 호스팅한다.

## 2. 브랜드 정체성

### 2.1 이름 해석: "Draft" + "URL"

**Draft**는 의도적인 이중 의미를 지닌다:

1. **A draft** (명사) — 미완성 문서, 작업 중인 것. 콘텐츠가 완벽하지 않아도 공유할 수 있다는 신호다. 심리적 장벽을 낮춘다: "그냥 초안이야."
2. **To draft** (동사) — 빠르게 작성하거나 스케치하다. 속도와 즉시성.

**URL**은 전달 매커니즘이다 — 브라우저만 있으면 누구나 콘텐츠에 접근할 수 있게 만드는 범용 주소.

**DraftURL**을 합치면: *"초안을 URL로 만들다."* 속도(드래프팅은 빠르다), 임시성(초안은 일시적이다), 접근성(URL은 범용적이다)을 함축한다.

### 2.2 브랜드 성격과 어조

**성격 특성:**

| 특성 | 설명 | 이것은 아님 |
|------|------|------------|
| **직접적** | 가능한 한 적은 단어로 의미를 전달한다. 마케팅 수사 없음. | 장황함, 영업 톤 |
| **자신감** | 자신이 잘하는 것을 알고 과대포장하지 않는다. | 오만함, 무시하는 태도 |
| **캐주얼** | 친근하되 유치하지 않다. 장난감이 아닌, 유용한 도구처럼 다가간다. | 격식체, 기업 톤 |
| **기술적** | 사용자의 지능을 존중한다. 과도하게 설명하지 않는다. | 수준 낮춤, 가르치는 태도 |
| **빠름** | 어조 자체가 빠르게 느껴진다 — 짧은 문장, 능동태. | 느리고 산만함 |

**어조 가이드라인:**

- **능동태** 사용: "HTML을 붙여넣으세요" (O) / "HTML이 붙여넣어질 수 있습니다" (X)
- **현재 시제** 사용: "URL이 준비되었습니다" (O) / "URL이 생성될 것입니다" (X)
- **간결하게**: 5단어로 말할 수 있으면 10단어를 쓰지 않는다
- **최상급 표현 회피**: "최고의", "가장 강력한", "혁신적인" 사용 금지
- **기술 용어는 그대로**: HTML, Markdown, URL, slug — 사용자가 이해하는 용어다

**어조 예시:**

| 상황 | 좋은 예 | 나쁜 예 |
|------|---------|---------|
| 기능 설명 | "HTML이나 Markdown을 붙여넣으세요. URL을 받으세요." | "저희의 혁신적인 플랫폼으로 문서를 손쉽게 공유 가능한 웹 경험으로 전환하실 수 있습니다." |
| 에러 메시지 | "문제가 발생했습니다. 다시 시도하세요." | "불편을 드려 진심으로 사과드립니다. 예기치 않은 오류가 발생했습니다." |
| 업셀 | "더 오래 유지하고 싶으세요? 로그인하세요." | "무료 계정을 만들어 문서의 잠재력을 최대한 발휘하세요!" |

### 2.3 타겟 사용자 페르소나

#### 페르소나 A: "AI 파워 유저" (주요 타겟)

- **누구**: LLM을 매일 사용하는 개발자, 제품 관리자, 콘텐츠 크리에이터
- **연령**: 25-40
- **행동**: ChatGPT나 Claude로 HTML/Markdown을 생성하고, 팀원이나 클라이언트에게 빠르게 공유해야 한다
- **고충**: AI 출력 복사, 파일 저장, 어딘가에 업로드, URL 획득 — 단계가 너무 많다
- **하는 말**: "Slack에 링크 하나만 던지면 되는데"

#### 페르소나 B: "빠른 공유자" (보조 타겟)

- **누구**: HTML이나 Markdown 파일을 지금 당장 공유해야 하는 모든 사람
- **연령**: 20-45
- **행동**: 일회성 문서(보고서, 데모, 프로토타입)를 24시간 동안 URL로 공유해야 한다
- **고충**: 파일 하나를 위해 호스팅을 설정하는 건 말도 안 된다
- **하는 말**: "HTML 파일 하나 때문에 서버를 띄우고 싶지 않아"

#### 페르소나 C: "팀 리드" (향후 / Phase 3)

- **누구**: 문서를 관리하는 엔지니어링 매니저, 테크 리드
- **연령**: 30-45
- **행동**: 팀 내에서 내부 문서, 스펙, 보고서를 가볍게 공유할 수단이 필요하다
- **고충**: Confluence는 과하고, Notion은 느리고, Google Docs는 HTML을 렌더링하지 못한다
- **하는 말**: "Gist와 본격적인 문서 사이트 사이의 뭔가가 필요해"

## 4. 비주얼 가이드라인

### 4.1 컬러 팔레트

현재 팔레트는 다크 모드 우선 디자인에 퍼플 액센트를 적용한 것이다. 개발자 친화적이고, 모던하며, 약간 프리미엄한 느낌을 전달한다.

#### 주요 색상

| 토큰 | Hex | 용도 |
|------|-----|------|
| `--bg-primary` | `#0a0a0f` | 페이지 배경. 약간의 블루 틴트가 있는 니어 블랙. |
| `--bg-secondary` | `#12121a` | 카드 배경, 패널. |
| `--bg-tertiary` | `#1a1a2e` | 호버 상태, 활성 탭, 입력 필드. |
| `--bg-elevated` | `#1e1e32` | 부상 표면(모달, 드롭다운). |

#### 액센트 색상

| 토큰 | Hex | 용도 |
|------|-----|------|
| `--accent` | `#7c5cfc` | 주요 액션 색상. 버튼, 링크, 활성 표시. |
| `--accent-hover` | `#6a48e8` | 액센트 요소의 호버 상태. |
| `--accent-glow` | `rgba(124,92,252,0.15)` | 히어로 요소 뒤의 은은한 발광 효과. |
| `--accent-subtle` | `rgba(124,92,252,0.08)` | 배경용 극히 연한 액센트(기능 카드 아이콘). |

#### 텍스트 색상

| 토큰 | Hex | 용도 |
|------|-----|------|
| `--text-primary` | `#e8e8f0` | 본문 텍스트, 헤딩. |
| `--text-secondary` | `#9090a8` | 보조 텍스트, 설명. |
| `--text-muted` | `#606078` | 플레이스홀더, 힌트, 비활성 텍스트. |

#### 보더 색상

| 토큰 | Hex | 용도 |
|------|-----|------|
| `--border-dark` | `#2a2a40` | 카드, 입력 필드의 기본 보더. |
| `--border-dark-hover` | `#3a3a55` | 보더 요소의 호버 상태. |

#### 상태 색상

| 토큰 | Hex | 용도 |
|------|-----|------|
| `--success` | `#34d399` | 성공 상태(URL 복사 완료, 퍼블리시 완료). |
| `--warning` | `#fbbf24` | 경고(한도 근접, 곧 만료). |
| `--danger` | `#f87171` | 에러, 파괴적 액션(삭제). |

#### 그라디언트

브랜드 그라디언트는 로고, 헤드라인 강조, 주요 CTA 버튼에 사용한다:

```
linear-gradient(135deg, #a78bfa, #7c5cfc, #60a5fa)
```

이 퍼플-투-블루 그라디언트는 액센트 컬러와의 통일성을 유지하면서 에너지와 현대적인 느낌을 전달한다.

### 4.2 로고 컨셉

**현재 구현:**
- 둥근 사각형(`rounded-lg`)에 그라디언트 배경(`from-accent to-[#a78bfa]`)
- 중앙에 흰색 볼드 글자 **"D"**
- 볼드 산세리프 워드마크 **"DraftURL"**과 함께 표시

**디자인 근거:**
- **"D"**는 모호하지 않으며 어떤 크기(파비콘, 헤더, 소셜 프리뷰)에서도 잘 작동한다
- 그라디언트 배경이 브랜드 액센트 컬러와 연결된다
- 둥근 사각형은 모던하고 다크/라이트 맥락 모두에서 잘 어울린다
- 워드마크는 센텐스 케이스를 사용하되 "URL"은 대문자로, 기술적 성격을 반영한다

**사용 규칙:**
- 헤더에서는 항상 아이콘 + 워드마크를 함께 표시
- 아이콘 단독 사용은 파비콘이나 앱 아이콘에 한정
- 최소 크기: 아이콘 24x24px
- 그라디언트 컬러나 글자를 변경하지 않는다

### 4.3 타이포그래피

**폰트 스택 (현재):**

```css
font-family: var(--font-geist-sans), 'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
```

- **주요**: Geist Sans (Vercel 시스템 폰트) — 깔끔하고 기하학적이며 개발자 친화적
- **대체**: Inter — 널리 사용 가능하며 유사한 웨이트와 비율
- **시스템 대체**: OS 네이티브 산세리프 스택으로 최대 성능 보장
- **모노스페이스**: Geist Mono — 에디터 패널의 코드 콘텐츠에 사용

**타입 스케일:**

| 요소 | 크기 | 웨이트 | 비고 |
|------|------|--------|------|
| 히어로 헤드라인 | `clamp(24px, 4vw, 36px)` | 800 (extrabold) | 반응형, 타이트한 자간 |
| 히어로 서브헤드라인 | `clamp(14px, 2vw, 16px)` | 400 (normal) | 보조 텍스트 색상 |
| 기능 카드 제목 | 15px | 600 (semibold) | 주요 텍스트 색상 |
| 기능 카드 본문 | 13px | 400 (normal) | 보조 텍스트 색상, 넓은 행간 |
| 버튼 텍스트 | 14-16px | 500-600 | 중요도에 따라 다름 |
| 네비게이션 | 14px | 500 (medium) | 보조 텍스트 색상, 호버 시 주요 색상 |

### 4.4 전반적 무드와 분위기

**키워드**: 다크, 클린, 개발자 중심, 빠름, 실용적, 약간의 프리미엄.

비주얼 언어가 전달하는 것:
- **다크 모드 = 개발자 기본값.** MVP에는 라이트 모드 토글이 필요 없다 — 타겟 사용자가 다크를 기대한다.
- **퍼플 액센트 = 또 다른 블루 SaaS가 아니다.** 퍼플은 블루 일색의 개발자 도구 사이에서 눈에 띄면서도 전문적인 느낌을 유지한다.
- **최소한의 크롬.** 넓은 에디터 영역, 사이드바 없음, 불필요한 패널 없음. 콘텐츠가 곧 제품이다.
- **은은한 발광 효과.** 히어로 뒤의 원형 그라디언트 발광과 버튼 그림자가 번쩍이지 않으면서도 에너지를 암시한다.
- **밀도 있되 어수선하지 않게.** 정보가 풍부한 UI(에디터 + 미리보기 + 기능 카드)와 섹션 간 넉넉한 여백.

**인스피레이션 (무드 참고, 카피 아님):**
- Linear (다크 모드, 퍼플 액센트, 개발자 우선)
- Vercel (클린, 빠름, 미니멀)
- Raycast (실용적, 키보드 우선 느낌)

## 5. 향후 브랜드 방향성

### 5.1 AI 기능 (Phase 2)

AI 편집 기능이 출시되면 브랜드 내러티브가 *"즉시 공유"*에서 *"즉시 공유 + 지속적 다듬기"*로 전환된다.

**메시징 진화:**

| Phase 1 (현재) | Phase 2 (AI) |
|----------------|--------------|
| "Paste. Publish. Share." / "붙여넣고, 배포하고, 공유하세요." | "Paste. Publish. Refine with AI." / "붙여넣고, 배포하고, AI로 다듬으세요." |
| "The fastest way to share your documents" / "문서를 공유하는 가장 빠른 방법" | "The fastest way to share and improve your documents" / "문서를 공유하고 개선하는 가장 빠른 방법" |

**비주얼 추가 사항:**
- AI 기능에는 보조 액센트를 사용한다 — AI 전용 요소에 **틸/시안** (`#60a5fa`, 이미 그라디언트에 포함) 고려
- AI 채팅 패널: 에디터와 구별되도록 미묘하게 다른 배경 적용
- AI 기능에 "AI" 배지 또는 스파클 아이콘 — 최소한으로 유지하고, 남용되는 스파클 이모지 트렌드를 피한다

**AI 기능 네이밍 규칙:**
- 설명적으로 유지: "AI Edit", "AI Refine" — 브랜딩된 하위 제품명을 붙이지 않는다
- 피할 것: "DraftAI", "SmartDraft" 등 AI를 별도 제품처럼 느끼게 하는 이름

### 5.2 유료 플랜

**무료 티어 포지셔닝:**
- 무료는 넉넉하게 느껴져야지, 기능이 잘린 느낌이면 안 된다. "문서 3개, 7일 만료"는 가치를 보여주기 충분하다.
- "제한된"이라는 단어를 절대 사용하지 않는다 — "무료 티어에 포함된 것..."으로 프레이밍한다

**Starter/Pro 네이밍:**
- **Starter** ($7/월): 정기적으로 공유하는 개인 사용자용. 핵심 메시지: "Your drafts, permanently." / "당신의 초안을 영구적으로."
- **Pro** ($15/월): 파워 유저용. 핵심 메시지: "Unlimited documents. Custom domains. Full analytics." / "무제한 문서. 커스텀 도메인. 전체 분석."
- **Team** ($12/인/월): 조직용. 핵심 메시지: "Your team's documents, one place." / "팀의 문서를 한 곳에."

**업그레이드 안내는 도움이 되는 톤으로, 강매하지 않는다:**

| 나쁜 예 | 좋은 예 |
|---------|---------|
| "지금 업그레이드해서 프리미엄 기능을 잠금 해제하세요!" | "문서 3개 이상 필요하세요? Starter는 월 $7입니다." |
| "무료 체험이 만료됩니다!" | "이 문서가 2일 후 만료됩니다. Starter로 유지하세요." |

**가격 페이지 어조:**
- 각 플랜이 가능하게 하는 것을 먼저 보여주고, 제한 사항은 뒤로 한다
- 명확한 비교 테이블을 제공한다
- 가장 인기 있는 플랜(Starter 또는 Pro)을 하이라이트한다

### 5.3 커뮤니티와 생태계

**개발자 커뮤니티:**
- CLI 도구를 오픈소스로 공개한다 — 신뢰와 채택을 구축
- npm에 `drafturl`로 퍼블리시(도메인과 일치)
- 메인 사이트에 `/docs` 또는 개발자 가이드를 운영한다

**콘텐츠 전략:**
- "Built with DraftURL" 쇼케이스 — 사용자가 만든 흥미로운 문서를 소개
- 유스 케이스 블로그 포스트: "Claude 출력을 3초 만에 공유하는 방법", "DraftURL로 내부 기술 스펙 관리하기"
- Twitter/X 활동: 실제 활용 사례 공유, 사용자 리트윗, 빠른 응답

**커뮤니티에서의 브랜드 보이스:**
- 퍼스널리티 브랜드가 아닌, 도움이 되는 도구로 존재한다
- 의견이 아닌, 팁을 공유한다
- 플랫폼이 아닌, 사용자의 창의성을 축하한다
