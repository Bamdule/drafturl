## 요약

전체적으로 분리가 잘 수행되었다. 기존 단일 파일(backend.md, frontend.md, infrastructure.md)은 삭제되었고, 새 경로로의 참조 업데이트도 대부분 완료되었다. 치명적 문제는 없으며, 주요 개선사항 4건과 사소한 개선사항 6건을 식별했다. 가장 중요한 것은 일부 중복 콘텐츠 정리와 독립 가독성 개선이다.

## 상세 검토

### 1. 중복 확인

#### (M-1) sandbox/CSP 정책 중복 -- security.md vs logic.md

`logic.md` 섹션 2에 CSP 헤더 전문과 sandbox iframe 설명이 포함되어 있고, `security.md` 섹션 5에도 동일한 정책이 기술되어 있다. 두 곳의 내용이 실질적으로 같으므로, 하나가 변경되면 다른 쪽도 동기화해야 하는 유지보수 부담이 생긴다.

- **제안**: `security.md` 섹션 5를 정규 위치로 두고, `logic.md`에서는 "보안 정책은 [security.md](security.md) 섹션 5를 참조"로 축소. 또는 반대로 logic.md에 구현 관점의 CSP 전문을 두고 security.md에서 참조.

#### (M-2) 토큰 저장 방식 중복 -- auth.md vs client.md

`auth.md` 섹션 4("프론트엔드 토큰 관리")와 `client.md` 섹션 3("토큰 관리")이 httpOnly 쿠키 저장, SameSite=Lax, Secure=true, Path 설정 등을 각각 기술한다. auth.md는 이미 "상세는 client.md 참조"라고 안내하면서도 3줄 요약을 포함하고 있어 내용이 미묘하게 다를 수 있다.

- **제안**: auth.md 섹션 4의 bullet point를 "프론트엔드 토큰 관리 전략은 [client.md](../frontend/client.md)를 참조한다"로 한 줄로 축소하고, client.md를 정규 위치로 확정.

#### (M-3) Rate Limiting 수치 3곳 산재

"비로그인 IP 분당 10회, 로그인 사용자 분당 30회"가 다음 3곳에 반복된다:
- `api.md` 섹션 1 (Rate Limiting)
- `security.md` 섹션 1 (입력 검증 표)
- `security.md` 섹션 6 (기술적 리스크 표)

수치가 변경되면 3곳을 모두 갱신해야 한다.

- **제안**: `api.md`를 정규 위치로 지정하고, security.md에서는 "Rate Limiting 정책은 [api.md](api.md)를 참조"로 변경.

### 2. 누락 확인

분리 과정에서 기존 내용이 빠진 항목은 발견되지 않았다. 각 하위 문서에 적절한 "요약" 섹션이 포함되어 있어, 기존 단일 파일의 내용이 보존된 것으로 판단한다.

다만 다음 사항은 기존 문서에서도 없었을 가능성이 있으나, 분리된 현재 구조에서 보완하면 좋을 항목이다:

### 4. 일관성 (수치/정책/스펙 충돌)

#### (M-4) R2 저장 용량 추산 불일치

`operations.md` 섹션 1의 MVP 비용 표에서 "Cloudflare R2 저장: 50MB << 10GB 무료"라고 표기했다. 그러나 일 100개 문서 x 평균 50KB(api.md에서 언급된 평균 크기) = 일 5MB, 월 150MB이다. 50MB는 1~2주 수준의 누적량에 불과하다.

- **제안**: "월 ~150MB (일 100개 x 50KB 가정, 만료/삭제 후 실 사용량은 더 낮음)"으로 수정하거나, 비로그인 24h 만료를 고려한 실 사용량 근거를 명시.

#### 기타 수치 일관성

다음 수치들은 모든 파일에서 일관된다:
- JWT Access Token 1시간, Refresh Token 7일
- 콘텐츠 최대 크기 5MB
- nanoid 8자리 slug
- 비로그인 24시간 만료
- sandbox="allow-scripts" (allow-same-origin 제거)
- HS256 알고리즘

## 잘된 점

1. **README.md 허브 패턴**: 각 서브디렉토리에 README.md를 두고 하위 문서 목록 테이블을 제공한 것이 좋다. 진입점이 명확하고 탐색이 쉽다.

2. **요약 섹션 일관성**: 모든 12개 파일에 "요약" 섹션이 있어 파일을 열자마자 내용을 파악할 수 있다.

3. **깨진 링크 없음**: 기존 경로에서 새 경로로의 전환이 깔끔하게 완료되었다. `product.md`, `market.md`, `domain.md` 등 외부 참조 문서의 링크도 모두 업데이트되었다.

4. **관련 문서 섹션**: 모든 파일 하단에 "관련 문서" 섹션이 있어 파일 간 탐색이 용이하다.

5. **docs/README.md 인덱스**: 전체 문서 트리 구조와 의존성 방향이 명확하게 정리되어 있다.

6. **관심사 분리가 적절**: backend는 API/인증/로직/보안, frontend는 페이지/클라이언트, infrastructure는 개발환경/배포/운영으로 분리 기준이 자연스럽다.

## 추가 고려사항

1. **문서 간 순환 참조 최소화**: 현재 backend/auth.md <-> frontend/client.md, backend/logic.md <-> backend/security.md 등 양방향 참조가 있다. 분리된 구조에서는 이런 양방향 참조가 불가피하나, 어느 쪽이 정규(canonical) 위치인지 명시하면 유지보수가 쉬워진다.

2. **design/task-plan.md와의 정합성**: git status에 `docs/design/task-plan.md`가 수정된 상태인데, 이 파일이 분리된 새 문서들을 참조해야 한다면 별도 확인이 필요하다.

3. **기존 리뷰 파일들과의 관계**: `docs/reviews/`에 `backend-review.md`, `frontend-review.md`, `infrastructure-review.md` 등 기존 단일 파일 기준 리뷰가 남아 있다. 이 리뷰들이 기존 경로를 참조하고 있다면 (이력 문서이므로) archived 표기를 고려할 수 있다.
