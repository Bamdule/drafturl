## 회원가입

### TC-AUTH-01: 이메일 회원가입 (정상)

**사전 조건**: 미가입 상태, `/auth/signup` 페이지
**테스트 단계**:
1. 이름 입력 (예: "테스트유저")
2. 미가입 이메일 입력 (예: "test@example.com")
3. 비밀번호 입력 (영문+숫자 8자 이상, 예: "test1234")
4. 비밀번호 확인 동일하게 입력
5. "회원가입" 버튼 클릭
**기대 결과**: `/dashboard`로 리다이렉트, 헤더에 사용자 이름 표시
**자동화**: 가능

### TC-AUTH-02: 이메일 회원가입 (중복 이메일)

**사전 조건**: 이미 가입된 이메일 존재
**테스트 단계**:
1. 이름 입력
2. 이미 가입된 이메일 입력
3. 비밀번호 / 비밀번호 확인 입력
4. "회원가입" 버튼 클릭
**기대 결과**: 서버 에러 메시지 표시 (빨간색 박스, "이미 사용 중인 이메일입니다" 등)
**자동화**: 가능

### TC-AUTH-03: 이메일 회원가입 (짧은 비밀번호)

**사전 조건**: `/auth/signup` 페이지
**테스트 단계**:
1. 이름, 이메일 입력
2. 비밀번호 7자 이하 입력 (예: "test123")
3. 비밀번호 확인 동일하게 입력
4. "회원가입" 버튼 클릭
**기대 결과**: "비밀번호는 최소 8자, 영문과 숫자를 포함해야 합니다." 클라이언트 검증 에러 표시, API 호출 없음
**자동화**: 가능

### TC-AUTH-04: 이메일 회원가입 (비밀번호 불일치)

**사전 조건**: `/auth/signup` 페이지
**테스트 단계**:
1. 이름, 이메일 입력
2. 비밀번호 입력 (예: "test1234")
3. 비밀번호 확인에 다른 값 입력 (예: "test5678")
4. "회원가입" 버튼 클릭
**기대 결과**: "비밀번호가 일치하지 않습니다." 클라이언트 검증 에러 표시, API 호출 없음
**자동화**: 가능

## 보안

### TC-AUTH-11: httpOnly 쿠키 검증

**사전 조건**: 로그인 상태
**테스트 단계**:
1. 브라우저 DevTools > Console 탭 열기
2. `document.cookie` 입력
**기대 결과**: `access_token`, `refresh_token`이 `document.cookie` 결과에 포함되지 않음 (httpOnly 설정으로 JavaScript에서 접근 불가)
**자동화**: 가능

### TC-AUTH-12: OAuth2 로그인 (Google/GitHub)

**사전 조건**: `/auth/login` 페이지, OAuth2 Client ID 설정 완료
**테스트 단계**:
1. Google 또는 GitHub 로그인 버튼 클릭 (현재 이메일 로그인만 구현된 경우 SKIP)
2. 외부 인증 페이지에서 인증 완료
3. 콜백 URL로 리다이렉트
**기대 결과**: `/dashboard`로 리다이렉트, 헤더에 사용자 이름 표시
**자동화**: 부분 가능 (OAuth2 인증 화면은 수동)
